# Database migrations

В этом проекте изменения схемы и важных данных БД хранятся в виде SQL-файлов в `database/migrations`.

## Правило работы

1. Сначала создать новый SQL-файл миграции в `database/migrations`.
2. Написать в него SQL-изменение.
3. Применить миграцию локально к локальной PostgreSQL через pgAdmin.
4. Проверить локально сайт, CRM и API.
5. Применить тот же SQL к продовой базе в Neon.
6. Закоммитить SQL-файл вместе с кодом.

## Именование файлов

Формат имени:

`YYYY-MM-DD-XXX-short-description.sql`

Пример:

`2026-05-06-001-add-preferred-contact-method.sql`

Где:
- `YYYY-MM-DD` — дата создания файла
- `XXX` — порядковый номер в этот день
- `short-description` — короткое описание изменения

## Важно

Не делать изменения схемы в pgAdmin или Neon без SQL-файла в репозитории.

Источник правды по изменениям БД — файлы в `database/migrations`.
