# Настройка базы данных для нового проекта

Этот документ описывает быстрый способ создать пустую PostgreSQL-базу для нового специалиста на основе актуальной схемы шаблона.

## 1. Что использовать

Для новой пустой базы использовать:

```text
database/schema.sql
database/seed-initial.sql
```

`database/schema.sql` содержит полный снимок актуальной структуры БД:

* таблицы;
* поля;
* primary keys;
* foreign keys;
* constraints;
* индексы;
* sequences.

`database/seed-initial.sql` содержит стартовые технические данные, которые нужны пустой базе для корректной работы проекта:

* базовые настройки онлайн-записи;
* базовые правила расписания по дням недели.

Эти файлы не содержат пользовательских данных: клиентов, заявок, сессий, отзывов, платежей или заметок.

## 2. Когда использовать `schema.sql` и `seed-initial.sql`

Эти файлы нужны, когда создаётся новый проект под нового специалиста.

Типичный сценарий:

1. Создать новую PostgreSQL/Neon базу.
2. Открыть SQL Editor или Query Tool.
3. Выполнить содержимое `database/schema.sql`.
4. Выполнить содержимое `database/seed-initial.sql`.
5. Получить пустые таблицы со всеми нужными полями, связями и стартовыми настройками.
6. Указать новый `DATABASE_URL` в `.env.local` и Vercel Environment Variables.
7. Проверить `/book`, CRM и публичные формы.

## 3. Как применять через pgAdmin

1. Открыть нужную базу.
2. Открыть Query Tool.
3. Вставить содержимое `database/schema.sql`.
4. Выполнить запрос.
5. Вставить содержимое `database/seed-initial.sql`.
6. Выполнить запрос.
7. Обновить раздел `Schemas → public → Tables`.
8. Проверить, что появились таблицы проекта.
9. Проверить, что в `booking_settings` и `schedule_rules` появились стартовые записи.

## 4. Как применять через Neon

1. Открыть проект Neon.
2. Создать новую database или branch.
3. Открыть SQL Editor.
4. Вставить содержимое `database/schema.sql`.
5. Выполнить запрос.
6. Вставить содержимое `database/seed-initial.sql`.
7. Выполнить запрос.
8. Проверить, что таблицы создались.
9. Проверить, что в `booking_settings` и `schedule_rules` появились стартовые записи.

## 5. Что делать после изменения схемы

Если в будущем меняется структура БД:

1. Создать новый SQL-файл в `database/migrations/`.
2. Применить его к нужной базе.
3. Обновить `database/schema.sql`, чтобы новый проект можно было развернуть одной схемой.
4. Если меняются стартовые настройки пустой базы, обновить `database/seed-initial.sql`.
5. Закоммитить migration, обновлённый `schema.sql` и при необходимости `seed-initial.sql`.

## 6. Важно

Не хранить в репозитории дампы с реальными данными.

В репозиторий можно добавлять только структуру БД без данных:

```text
pg_dump --schema-only
```

И безопасные стартовые настройки без персональных данных:

```text
database/seed-initial.sql
```

Не добавлять:

* клиентов;
* заявки;
* сессии;
* заметки;
* отзывы;
* платежи;
* email;
* телефоны;
* любые персональные данные.
